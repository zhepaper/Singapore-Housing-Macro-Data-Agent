# Singapore Housing Macro Data Agent

## Overview

This repository implements an agent-assisted data workflow for monitoring public indicators relevant to Singapore's **private non-landed residential** sale and rental markets. It supports official-source research and onboarding, preserves downloaded evidence, executes approved data transformations deterministically, and produces a verified analytical report.

The system is designed for evidence-based market monitoring. It is not a trained forecasting model, a causal estimator or a property-transaction database.

## Submitted Demonstration

The submission uses an information cut-off of **1 October 2026** and includes three reviewer-facing deliverables:

- [`ENGINEERING_REPORT.pdf`](ENGINEERING_REPORT.pdf): the formal five-page engineering report covering system design, data processing, reliability, evaluation and LLM use.
- [`sample_run/submission/stage4/final_report.md`](sample_run/submission/stage4/final_report.md): the analytical report generated by the workflow.
- [`sample_run/submission/`](sample_run/submission/): the corresponding Stage 3 and Stage 4 audit trail, including the frozen plan, validated evidence, claim ledger and verification result.

The submitted snapshot path is the recommended reproducible reviewer demonstration. The repository also implements the earlier agent-assisted research, source discovery, mapping, preparation and human-approval stages for interactive use.

## Quick Start

Python 3.11 or later is required. From a fresh clone or extracted repository:

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev,llm]'
```

Run the complete reviewer-facing workflow from the approved raw snapshots and `FrozenDataPlan` to a verified report:

```bash
.venv/bin/python scripts/run_submission_pipeline.py \
  --output outputs/submission_run \
  --print-report
```

This command is offline, deterministic and requires no API key. It verifies snapshot checksums, normalises and validates the approved portfolio, applies only frozen transformation rules, builds the `ValidatedEvidenceBundle`, regenerates the report and verifies every quantitative claim.

The regenerated report is written to:

```text
outputs/submission_run/stage4/final_report.md
```

Run the complete offline test suite:

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

The submitted version passes **186 tests**; one live-endpoint smoke test is skipped by default so that normal reproduction remains network-independent.

## Run with Live Sources

The formal submission command intentionally uses the preserved snapshots and does not silently replace them with newly downloaded data. This keeps the reviewed result reproducible.

For an optional operational check against the current official endpoints, a retained compatibility runner is available:

```bash
.venv/bin/python old/run_workflow.py \
  --mode live \
  --as-of 2026-10-01 \
  --output outputs/live-report.md
```

Live execution depends on endpoint availability, current schemas and release timing, so its result may differ from the submitted snapshot run. Cached fallback is never automatic; adding `--allow-cached-fallback` labels the run as partial and records an operational warning.

The preserved inputs are under [`sample_run/raw/`](sample_run/raw/). ## Tests

The default suite covers research and onboarding contracts, raw preservation, schema mapping and repair, frozen-plan integrity, normalisation, transformation policies, missing and stale data, exact-period calculations, provenance, Stage 4 composition, claim verification and end-to-end reproducibility.

The live endpoint smoke test is opt-in:

```bash
RUN_LIVE_TESTS=1 PYTHONPATH=src \
  .venv/bin/python -m unittest tests.test_live_sources -v
```

It is not required for the reproducible reviewer run.

## Optional Agent-Assisted Workflow

Beyond the submitted snapshot path, the repository implements the full governed workflow:

```text
User scope
-> LLM-assisted predictor research
-> human predictor approval
-> official-source discovery and raw capture
-> mapping and preparation recommendations
-> human data and transformation approval
-> FrozenDataPlan
-> deterministic Stage 3
-> evidence-bound Stage 4
-> verified final report
```

LLMs are used only for semantic tasks such as research, unfamiliar-schema interpretation, preparation recommendations and optional qualitative writing. Human approval controls material data decisions, while numerical transformations and final claim verification remain deterministic. Optional online agent nodes require the user to provide their own model-provider credentials; no credentials are included in the repository.

Configuration and detailed execution of the interactive path are documented in [`docs/end-to-end-workflow.md`](docs/end-to-end-workflow.md).
